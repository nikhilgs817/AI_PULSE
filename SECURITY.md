# Security reporting

Report suspected vulnerabilities or signing-process misuse through this repository's **Security → Advisories → Report a vulnerability** feature when available. Do not include tokens, kubeconfigs, private monitoring databases, model conversations or private keys in public issues. If private reporting is unavailable, open an issue containing only a request for a private contact channel.

Include the affected version/commit, platform, relevant component and a minimal reproduction without personal data. Do not upload executable malware or attempt to access other users' hosts. The maintainer reviews reports on a best-effort basis; no response-time guarantee is offered.

This early preview is intended for small personal installations. Use only trusted packages and administrator-authorized deployment. Do not disable platform security controls to run an unsigned build. Keep hub administration credentials private, revoke compromised agents and coordinate hub/database restoration as described in the central guide.

See the [code signing policy](CODE_SIGNING_POLICY.md) and [privacy policy](PRIVACY.md).
